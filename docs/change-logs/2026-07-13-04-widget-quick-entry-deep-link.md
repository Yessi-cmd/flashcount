# Widget quick-entry deep link

## Purpose

Turn the existing unreferenced WidgetKit source into a real app extension and make every supported widget family open FlashCount directly at quick entry.

## Affected files

- `project.yml`
- `FlashCount/Info.plist` (generated by XcodeGen from `project.yml`)
- `FlashCount/Core/AppDeepLink.swift`
- `FlashCount/Views/MainTabView.swift`
- `FlashCountWidget/FlashCountWidget.swift`
- `FlashCountWidget/Info.plist`
- `FlashCountTests/AppRoutingTests.swift`

## Behaviour changes

- The generated Xcode project includes and embeds a `FlashCountWidget` extension for lock-screen circular, lock-screen rectangular, and home-screen small families.
- Tapping any FlashCount widget opens `flashcount://quick-entry` and presents quick entry directly.
- Deep links received during first-launch onboarding remain queued until onboarding finishes.
- The parser also supports typed report deep links for future local entry points.

## Verification performed

- Added unit coverage for accepted and rejected quick-entry URLs and typed report-period parsing.
- `xcodegen generate` completed successfully and regenerated the Xcode project from `project.yml`.
- An unsigned Debug build for the generic iOS Simulator destination succeeded, including embedded-widget validation.
- All 59 unit tests passed on an iPhone 17 Pro simulator running iOS 26.2.
- All 4 UI smoke tests passed on the same simulator.
- `git diff --check` completed without whitespace errors; the generated project lists the app, unit-test, UI-test, and Widget targets.

## Remaining limitations

- Widgets contain a launch action rather than inline amount entry because the complete transaction form requires category and persistence context from the main app.
- Installing the extension on a physical device still requires a development team and provisioning profile that cover both bundle identifiers.
